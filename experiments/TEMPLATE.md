# 实验：填写具体主题

复制到实验计划或执行目录后填写。计划状态为“未执行”；执行日期、版本与结果仅按实际情况记录，不能把预期行为填入实测结果。

| 字段 | 填写内容 |
| --- | --- |
| 状态 | 未执行；执行后改为进行中、已完成或中止，并保留未执行用例 |
| 所属部分 | 从机械臂、无人机、联合联调中选择一项 |
| 负责人及参与者姓名 / 账号 | 本人填写；联合实验区分牵头人和双方参与者 |
| 关联任务、PR 与计划 | 填写实际 Issue、代码归档 PR 和实验计划链接 |
| 执行日期、起止时间与时区 | 未执行时保持“未执行”；执行后使用实际时间，例如注明 Asia/Shanghai |
| 运行编号 | 执行时分配，确保一次运行对应一套日志和配置 |
| 硬件与设计版本 | 记录实物型号、设备标识和设计文件版本；联合实验分别列明两组版本 |
| 无人机平台 | 雷迅 X25 EVO + Jetson Orin；涉及该平台时补充实际固件、系统、依赖与连接配置，机械臂独立实验可写“不涉及” |
| 代码仓库、路径与完整 SHA | 先将代码归档到仓库再填写完整 Git SHA；联合实验分别列出两组代码路径，未归档时写“尚未归档，不执行” |
| 本地改动 | 无改动时写“无”；有改动时保留可复现补丁并说明对应基础 SHA |

## 目标、范围与判断条件

写明本次要验证的行为、观测方法与通过条件，注明哪些能力不在本次范围。状态机输出、命令 ACK、实体动作与承重能力分别判断。没有测量方法或未满足前置条件时不填写“通过”。

## 前置条件与分工

列出每组交付内容、操作与记录分工、设备状态、接口确认项及停止条件。人员姓名与账号由本人填写；未满足的条件明确列出，未满足前保持“未执行”。

## 参数与配置

逐项填写实际采用的参数名称、数值、单位、来源与配置文件路径；相机安装角度、开关偏移等使用实测值并保留测量方法。代码默认值只作为配置来源记录，不作为已验证的精度或性能。

## 实验步骤与用例

按“准备 → 输入或故障注入 → 观察 → 结束与恢复”编写每个用例。实际执行时记录步骤偏差；未执行时填写计划步骤。

| 用例 | 输入或触发条件 | 判断条件与证据 | 执行状态 | 实测结果与日志位置 |
| --- | --- | --- | --- | --- |
| 填写用例名称 | 填写输入、初始条件及故障注入方式 | 填写预期行为、观测方法和通过条件 | 未执行 | 未执行，不预填结果 |

## 原始数据与附件

原始日志、大视频和大型数据存入团队共享存储的 `Hover-Drone/experiments/<本次执行记录目录>/raw/`。填写实际访问链接、文件清单、获取方法及必要校验值；仓库保存本记录、配置、小型结果图和汇总表。未生成数据时写“未生成”。

## 结果、异常与结论

执行后填写观测结果、测量值、异常、判断依据和结论；将直接观测与推测分开，注明无法判断的原因。未执行时保持“未执行，无实测结论”。

## 后续事项

关联问题和复验任务；新运行使用新的运行编号，保留本次原始记录。
