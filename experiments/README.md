# 实验计划与记录

这里统一维护机械臂组、无人机组及两组联合实验的计划与记录。实验归属按工作内容确定，不另设团队。当前已有[固定横杆对准与触碰闭爪台架实验计划](bench-contact/README.md)，**状态为未执行**。

## 两组如何分工

| 实验归属 | 记录重点 | 协作方式 |
| --- | --- | --- |
| 机械臂组 | 夹爪机构、执行器、开关读取、实体动作及结构版本 | 机械臂组组织；涉及安装、供电或命令反馈时请无人机组共同确认 |
| 无人机组 | 机载视觉、目标对准、飞控数据与代码行为 | 无人机组组织；涉及触碰与闭爪时请机械臂组共同确认 |
| 联合联调 | 两组接口、触碰后闭爪请求及实体动作对应关系 | 指定一位牵头人，分别记录双方交付版本和观测结果；姓名与账号由本人填写 |

## 记录流程

1. 在 Issue 中写明所属组、目的、交付记录、判断条件及分工。复制 [TEMPLATE.md](TEMPLATE.md) 编写计划，先把状态设为“未执行”；人员姓名与账号由本人填写。
2. 执行前固定代码、硬件和配置版本。源代码需先由所属组归档到仓库，经 PR 合并后记录完整 Git SHA；现有横杆原型尚未导入，不能以当前文档提交代替实验代码版本。联合实验分别写明两组路径和版本。
3. 对照[接口约定](../docs/interfaces.md)确认前置条件、测量方法、停止条件与异常处理。已确认平台为雷迅 X25 EVO 与 Jetson Orin；实际设备标识、固件、系统、依赖及安装配置仍须按实物记录，不能由平台名称推定兼容性。
4. 一次执行建立 `YYYY-MM-DD_<机械臂或无人机或联合>_<主题>/`，日期使用实际执行日期。目录内保存 `README.md`、实际参数和小型汇总附件；计划目录与执行记录相互链接。尚未执行时不预填执行日期或结果。
5. 执行中保留原始日志、输入数据和异常现象。原始日志、长视频、大型数据及模型权重放团队共享存储的 `Hover-Drone/experiments/<执行记录目录>/raw/`，在记录中补充真实可访问链接、文件名、获取方法及必要校验值。
6. 执行后逐项填写实测结果与证据，并标为“通过”“未通过”或“无法判断”；未执行的用例保持“未执行”。记录通过 PR 检查后合入，失败与未完成项关联后续 Issue。

程序进入某个状态、发出闭爪命令、收到命令 ACK、观察到实体闭合、确认承重是不同证据，需要分别记录。现有原型没有载荷转移、承重确认或停桨流程；闭爪台架记录不作为这些能力的验收结果。

同一条件的重复试验使用不同运行编号；后续改动通过新记录或注明时间的补充说明关联，保留原始失败记录。
