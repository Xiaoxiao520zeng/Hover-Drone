## 目标与实验边界

检查固定横杆的视觉对准、开关触碰、状态转移、零运动请求和一次闭爪请求之间的逻辑对应关系，并检查缺失输入与飞控数据未就绪时的行为。实体夹爪闭合需要机械臂组单独观察、记录，不能由状态或 ACK 推定。

本计划只覆盖台架输入与闭爪链路。现有代码没有载荷转移、承重确认、停桨或完整停栖流程，本次不开展这些验收，也不据此宣称完成自主停栖。所有用例先使用可控输入与假链路检查；实物台架仅在两组确认台架状态、夹爪执行接口与停止方式后开展，不进行飞行。

## 已知代码行为与待确认项

- 状态机包括 `ALIGN`、`APPROACH`、`CONTACT`、`ABORT`。`CONTACT` 表示在接近阶段读到触碰，不表示实体夹爪已闭合。
- 进入接近阶段后触碰会产生零三轴速度、零偏航角速度和闭爪请求；真实链路只有在零运动请求发送成功后才调用闭爪接口。这里的零偏航角速度不是停转电机或停桨。
- 当前真实飞控适配器面向 ArduCopter 的 `GUIDED`，并检查解锁状态、心跳、姿态与本地位置数据。雷迅 X25 EVO 的实际固件与接口兼容性仍需无人机组核对，不能仅凭硬件型号认定已经适配。台架逻辑检查使用假链路，不为满足检查而给实机解锁。
- 闭爪 ACK 超时只输出诊断信息并结束本次 ACK 等待，不会自动让状态机从 `CONTACT` 变为 `ABORT`，也不会自动重发闭爪命令。ACK 收到与否均需独立观察实体动作。
- 默认阈值是原型配置，不代表已验证的精度、速度或可靠性。执行前保存本次实际配置及其测量依据。

## 执行步骤

1. 在对应 Issue 中由双方确认范围、分工和前置条件。代码归档合并后，将实际代码完整 SHA、硬件与环境版本、依赖清单记录到本次执行记录。
2. 从[实验模板](../TEMPLATE.md)创建使用实际执行日期的记录目录，分配运行编号；保存全部实际参数、偏移测量方法、假链路或输入数据版本。
3. 先用假链路和可控输入逐项执行下表，记录输入时间、状态、输出请求及诊断信息。每个用例重新建立独立运行状态，避免前一用例的终止状态影响下一用例。
4. 逻辑检查完成后，两组核对实物台架条件。使用不接真实飞控端点的预览，人工移动固定组件或目标验证视觉和真实开关输入；记录这是人工台架对位，而不是飞行对位。没有符合前置条件的夹爪执行接口时，实体闭合项保留“未执行”。
5. 如具备已核对的独立台架夹爪接口，由机械臂组执行实体动作检查，分别记录触碰、闭爪请求、实际动作及限位情况；不能把无飞控链路时的 `SIMULATED` 输出作为实体动作证据。
6. 遇到输入不符合计划、状态与请求不一致、夹爪行程异常或日志缺失时结束当前用例，保留异常，不直接修改原始结果。恢复后以新的运行编号复验。
7. 整理每项的实际结果、原始证据和遗留问题，通过 PR 由两组共同检查；未执行的用例保持原状态。
