# 成员与分工

项目设一位**项目总负责人**，下设**机械臂组**和**无人机组**，各组内部自行分配具体工作。

| 角色 | 当前人员 | 职责 |
| --- | --- | --- |
| 项目总负责人 | **Air.Zhen** | 维护总体目标与阶段计划，协调两组依赖和接口分歧，汇总交付状态并组织联合验收 |

总负责人统筹整个项目，两组负责人对本组设计、代码、物料与验证结果负责。组负责人同时承担接口与物料清单的核对责任，具体维护人员可以兼任。成员在下表填写自己的姓名和 GitHub 账号，不预先代填人员。

| 团队 | 工作范围与资料位置 | 组负责人 / GitHub 账号 | 组内成员 / 接口联系人 | 本组 BOM 汇总负责人 |
| --- | --- | --- | --- | --- |
| 机械臂部分 | 夹持机构与执行控制、触碰反馈、独立夹持及承重验证；资料和代码放 [robotic-arm/](../robotic-arm/README.md)，维护 [robotic-arm/bom.csv](../robotic-arm/bom.csv) | 本人填写姓名 / @账号 | 成员及接口联系人本人填写，可兼任 | 维护人本人填写，由组负责人核对 |
| 无人机部分 | X25 Evo 飞控、Jetson Orin 机载平台、机体集成、视觉对准与飞行任务衔接；资料和代码放 [drone/](../drone/README.md)，维护 [drone/bom.csv](../drone/bom.csv) | 本人填写姓名 / @账号 | 成员及接口联系人本人填写，可兼任 | 维护人本人填写，由组负责人核对 |

项目计划、接口等公共资料放 [docs/](README.md)，两组实验记录统一放 [experiments/](../experiments/README.md)。这些是共享内容，不另设团队。

各组目录中的 `design/` 放设计源文件与必要导出件，`code/` 放本组代码，`bom.csv` 记录本组物料。具体工作通过组内任务分配。组内成员提供各自使用物料的信息，由本组 BOM 汇总负责人核对并维护清单；清单中的计划项和候选项不代表已经采购、入库或完成验证。

## 两组交付边界

| 工作 | 机械臂组负责 | 无人机组负责 | 总负责人协调或验收 |
| --- | --- | --- | --- |
| 结构与装配 | 夹爪、执行机构、连接尺寸、工作空间与承重试验 | 机体、搭载连接、桨盘净空、整机质量与重心 | 确认两组安装边界与阶段交付版本 |
| 供电与接线 | 提供执行器和开关接口、电压电流需求及线束说明 | X25 Evo、Jetson Orin 供电与整机配电，核对组间供电能力 | 协调冲突项，要求保留检查记录 |
| 代码与状态 | 触碰采集、执行机构控制与状态定义 | 感知、目标对准、飞控通信与任务状态衔接 | 明确每次联调目标，汇总未通过项目 |
| 物料 | 提供本组结构件、执行器、传感与接插件需求 | 提供飞控、计算平台、机体动力及配电需求 | 核对两组重复项和遗漏项，不代填器件规格 |
| 验证与交付 | 独立动作、夹持及承重记录 | 定位、通信、对准和飞行模式衔接记录 | 组织两组按需求表逐项联合验收 |

## 任务与交接

- 每个 Issue 写明所属组并指定一位负责人，协作成员在描述中列出；联合任务指定一位牵头人，并列出双方参与者。
- 各组维护自己的 README，确保其他成员能找到文件、搭建所需环境并复现结果。
- 双方接口联系人共同维护[接口约定](interfaces.md)。涉及安装、承重、供电或命令反馈的改动，在 PR 中邀请另一组检查。
- 两组共同确认技术需求、联调条件和验证结果，总负责人协调阶段计划并组织联合验收，阶段目标见[项目计划](project-plan.md)。
- 交接时说明当前版本、未完成任务、已知问题和数据位置，并更新本表。

本表只记录项目协作所需的信息，联系方式放团队已有的沟通渠道。
