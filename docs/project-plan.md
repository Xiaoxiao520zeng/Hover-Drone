# 项目计划

本页为实施与验收初稿，供团队按实测结果修订。以下需求和阶段条件是计划，均不表示已完成实机验证。人员姓名与账号由成员在[分工表](team.md)自行登记。

项目由总负责人统筹，下设[机械臂组](../robotic-arm/README.md)与[无人机组](../drone/README.md)。总负责人确认总体目标、协调两组进度并组织联合验收；两组分别交付原型，共同确认[接口约定](interfaces.md)与实验条件。

## 项目目标与交付物

目标是在 GPS 拒止条件下，通过机械臂抓取树枝或圆柱物，使无人机实现可验证的悬挂停留。实施顺序为：固定标记横杆上的对准与触碰闭爪原型、机械承重验证、载荷转移与动力管理、联合悬挂演示。每一步分别验收，不能用闭爪指令或飞控 ACK 代替承重与停留证据。

| 交付物 | 内容与归档位置 |
| --- | --- |
| 机械臂原型 | 结构、执行机构和触碰反馈的实现；可编辑设计、导出件、装配说明放 `robotic-arm/design/`，代码与标定说明放 `robotic-arm/code/`，本组物料维护于 `robotic-arm/bom.csv` |
| 无人机原型 | 机体、动力供电、飞控与机载计算的集成；设计与接线放 `drone/design/`，代码、配置示例和运行说明放 `drone/code/`，本组物料维护于 `drone/bom.csv` |
| 平台与接口记录 | 设备身份、软件版本、两组安装与通信接口、实测参数及适用条件；权威文件保存在所属组目录，由 `docs/` 索引 |
| 联合实验与最终交付 | 逐阶段实验记录、代码提交号、硬件版本、原始数据索引、异常记录，以及另一位成员可执行的装配与运行指南，统一由 `experiments/` 和两组 README 导航 |

两组内部按实际任务分工；确有仿真需求时，代码和模型归入所属组。

## 已确定平台与候选试验路线

| 项目 | 当前依据与下一步交付 |
| --- | --- |
| 飞控 | 项目已确定采用 **雷迅 X25 Evo**；[官方说明](https://doc.cuav.net/controller/x25-evo/)列明硬件兼容 ArduPilot 与 PX4。无人机组登记实物硬件标识、已装固件名称与版本、可用接口及配置备份，再验证与原型控制接口的兼容性；硬件支持不等于已确认运行 ArduCopter GUIDED |
| 机载平台 | 项目已确定采用 **Jetson Orin**。无人机组读取设备标识并登记具体子型号、载板、系统与 JetPack 版本、供电方式；提交环境安装记录和实际运行命令，不将家族名称当成完整设备配置 |
| 现有候选代码 | 工作区 `rod_perching_test` 包含固定横杆视觉、目标锁定、对准接近、触碰与闭爪原型；这是可供归档和验证的输入，不是已确认的整机方案或测试结果 |
| 候选视觉与接触方案 | 原型面向 OAK-D Pro 的 RGB-D、红色胶带标记的近水平固定横杆，以及夹口微动开关。相机、开关与安装关系需由两组评估、登记并验证；不据现有代码声称设备已到位 |
| 候选软件环境 | 原型说明要求 Python 3.10 及以上，依赖文件包含 DepthAI 3、NumPy、OpenCV、pymavlink 和 pyserial。无人机组在所用 Orin 环境安装并记录实际版本，再形成可复现依赖基线 |
| 候选飞控接口 | `flight_io.py` 面向已解锁、具备有效本地定位与姿态的 ArduCopter GUIDED。无人机组先核对 X25 Evo 的实际固件与消息支持；兼容则逐项验证，不兼容则适配接口后重新验证，不直接带入飞行试验 |

现有状态机为 `ALIGN → APPROACH → CONTACT`，异常进入 `ABORT`。触碰时程序尝试先发三轴零速度和零偏航角速度，再发一次闭爪命令；它没有实现载荷转移、停桨或释放恢复流程。`CONTACT` 不证明实体已闭合，ACK 不证明已承重，发送零速度也不证明飞行器已停稳。

现有视觉拟合的是标记可见表面，不等同于自然枝中心线、枝条强度或可承重点。无标记自然枝识别、自主找枝、自动起降及复杂环境避障不属于当前闭爪原型的验收范围；若开展这些扩展，应先单独定义场景与需求，不能据固定横杆结果宣称自然枝自主停栖已经实现。

## 数值指标的测量与确认任务

尚无实测依据的数值不直接填成性能承诺。两组先完成下列任务，在所属组的设计或标定记录中给出测量方法、数值、单位、误差和适用版本；涉及双方的边界写入接口文档。参数应在对应试验开始前确定，不能根据结果事后调整通过条件。

| 任务 | 负责角色 | 交付与确认方法 |
| --- | --- | --- |
| PARAM-01：定义试验杆与夹持范围 | 机械臂组牵头、无人机组协作 | 测量样杆直径、表面、倾角及固定方式；测量夹口开度和有效夹持区，列出可进入当前试验的样杆集合与排除条件 |
| PARAM-02：测量安装与重心 | 两组共同 | 测量安装尺寸、两组质量、整机重心及机械臂动作包络；检查与桨盘、机体和线束的间隙，保存图纸与实物照片 |
| PARAM-03：标定相机与触碰位置 | 两组共同 | 测量相机至触发触头的前右下偏移和安装角；用已知位移、方向与距离对比显示误差，记录近距深度失效范围 |
| PARAM-04：确定对准与接近参数 | 无人机组牵头、机械臂组协作 | 先量化夹口捕获余量、定位误差和实际减速距离，再确定容差、起始距离、速度、持续时间与超时；在无动力台架验证指令方向和边界 |
| PARAM-05：确定供电条件 | 两组共同 | 核对设备供电要求，测量空闲与动作时的电压、电流及异常表现；确定电源与连接器方案，记录供电异常时的状态与恢复方式 |
| PARAM-06：确定载荷与保持条件 | 机械臂组牵头、无人机组协作 | 依据整机实测质量与安装方式提出静载工况、保持时间、滑移和变形判据；在独立台架完成分级加载记录，再形成可用范围 |
| PARAM-07：确定各阶段试验通过条件 | 两组共同、总负责人组织 | 根据对应阶段已有的定位、夹持或承重证据，在该阶段试验前确定工况、重复次数、允许误差、成功判据及中止条件；进入动力管理阶段前，另行明确状态转换和人工接管方式 |

原型源码中的初始容差、速度与时限仅用于代码联调参考，不作为本项目实测能力或最终验收值。关键参数未经上述测量确认，对应阶段不能宣告通过。

## 可验证的需求

本表规定交付与验收口径，不维护 Issue 的进度副本。实际任务在 GitHub Issues 中关联 REQ 或 PARAM 编号并指定成员；本页不预设 Issue 编号。

| 编号 | 需求 | 负责角色 | 可执行验收与证据 |
| --- | --- | --- | --- |
| REQ-001 | 现有资料与原型可追溯、可运行 | 两组分别交付 | 归档被采用的设计和代码，保留来源与版本；另一位成员按 README 安装依赖并运行原型演示，保存命令、环境和状态输出。演示结果单独标为模拟，不能作为实机结果 |
| REQ-002 | 已选平台有设备与兼容性记录 | 无人机组 | 完成 X25 Evo 实际硬件与固件、Orin 子型号与 JetPack 登记；保存飞控通信、姿态/本地定位数据及所需控制消息的验证记录。接口不兼容时交付适配结果，未适配前不进入受控接近试验 |
| REQ-003 | 两组安装、质量重心及供电可核查 | 两组共同 | 完成 PARAM-02、05，对照同一版安装与接线图逐项核对实物，记录质量、重心、动作间隙和供电测量；解决影响后续试验的干涉或供电问题 |
| REQ-004 | 机械臂能完成可观测的抓取与释放 | 机械臂组 | 在固定台架按 PARAM-01 的样杆集合逐项测试开合、限位和触碰反馈；对照指令与实体动作记录成功及失败，区分触碰、闭合和承重状态，不以单个开关代替全部状态证明 |
| REQ-005 | 候选视觉路线有误差与适用范围记录 | 无人机组牵头、机械臂组协作 | 完成 PARAM-03，用已知位置的标记杆检验前右下和偏航误差；记录有效深度、遮挡、近距失效和多杆歧义；不能可靠观测时不得继续自动接近 |
| REQ-006 | 受控接近前具备定位与人工接管条件 | 无人机组 | 在已登记固件与定位方案上完成定点能力和模式接管验证，按 PARAM-04、07 记录误差及边界；起飞、解锁与模式切换由既定操作流程负责，不能假设现有脚本会完成这些动作 |
| REQ-007 | 固定标记横杆完成对准、触碰与实体闭爪 | 两组共同 | 先无动力台架，再按确认条件进行受约束联调；逐次记录目标、偏移、状态、开关、停止请求、闭爪命令及实体动作，核对零速度请求先于闭爪请求。仅在观察到实体闭爪后判定本阶段完成，不宣称承重或停桨 |
| REQ-008 | 异常情形有可复现的中止与接管证据 | 两组共同 | 用受控输入分别验证视觉丢失/过期、目标歧义、开关断流、超差、接近超时和飞控未就绪；记录中止状态、零速度请求及实际响应。链路失效时验证独立接管流程，不能将未送达的停止请求视为停稳 |
| REQ-009 | 独立证明夹持与结构承重能力 | 机械臂组牵头、无人机组协作 | 按 PARAM-06 的分级载荷与保持条件完成独立台架试验，记录载荷、持续时间、滑移、变形、夹持状态与失效现象；证据覆盖拟用于联合试验的工况后，才进入载荷转移阶段 |
| REQ-010 | 载荷转移与动力管理有独立实现和验证 | 两组共同 | 在 REQ-009 通过后，制定并实现承重确认、动力调整、异常中止的状态与操作流程，先验证受约束工况；记录实体受力依据、动力状态与全过程，不在仅有触碰或 ACK 时自动判为承重并停桨 |
| REQ-011 | 悬挂后的释放与恢复有明确流程 | 两组共同 | 根据动力管理方案实现所需控制或人工步骤，明确恢复支撑、解除夹持和中止条件；在受约束试验中检查动作次序及反馈，形成可复现记录，不将尚未实现的释放或恢复能力写成自动功能 |
| REQ-012 | 联合演示与交付可由他人复核 | 两组交付、总负责人组织验收 | 按 PARAM-07 的事先确认工况完成悬挂停留与恢复验证；逐项关联上述需求、硬件版本、代码提交和原始数据。另一位成员依照指南复核运行与记录，未通过项单独列出，不以展示视频替代测量证据 |

## 以完成条件推进的里程碑

进度按下列阶段完成条件推进；具体任务的目标日期在对应 Issue 中登记。阶段交付是验收门槛，不是完成状态；当前进度以 Issues 与实验记录为准。

| 阶段 | 应交付的内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| M0：资料、平台与接口基线 | 两组目录与资料索引、设备登记、接口初稿、实验参数测量任务 | REQ-001、002 的资料与兼容性检查完成；双方联系人在分工表登记，后续试验有明确负责人和所需设备清单 |
| M1：两组独立原型 | 安装与供电检查、机械臂动作记录、视觉标定及定位验证 | REQ-003 至 006 完成；对应测量任务给出数值与适用条件，能够分别复现两组原型行为 |
| M2：固定标记横杆触碰与闭爪 | 无动力及受约束联调记录、异常用例、实体闭爪证据 | REQ-007、008 完成；明确本阶段终点为实体闭爪，承重与动力管理仍按后续阶段验证 |
| M3：独立承重与保持 | 分级载荷试验、保持与失效记录、适用载荷范围 | REQ-009 完成；两组确认用于载荷转移试验的工况和结构依据 |
| M4：载荷转移与动力管理 | 独立实现的状态/操作流程、受约束动力管理和恢复记录 | REQ-010、011 完成；不能以 M2 的触碰闭爪结果跳过此阶段 |
| M5：联合悬挂验收与交付 | 联合实验报告、两组装配与运行指南、最终版本清单和数据索引 | 总负责人组织 REQ-012 验收，两组逐项复核事先确定的通过条件，并明确成果适用场景及未实现的扩展 |

## 首批可建立的任务

以下是任务拆分建议，创建 Issue 时引用本页编号，实际状态仅在 Issue 中更新。

1. 无人机组完成 X25 Evo、Jetson Orin 的实物与软件版本登记，交付 REQ-002 的接口兼容性检查记录。
2. 两组清点现有结构、接线与原型代码，按交付目录归档；明确采用和保留为候选的内容，交付 REQ-001 的复现记录。
3. 机械臂组启动 PARAM-01、06；两组共同完成安装、重心、相机偏移与供电测量任务，并把结果关联到接口文档。
4. 无人机组依据实测夹口余量与定位误差提出接近参数，两组在无动力台架复核后安排 M2 所需实验。
5. 总负责人组织两组核对阶段依赖和 PARAM-07 的验收条件；成员姓名与账号在分工表及任务中自行登记。
