# 机械臂与无人机接口约定

接口草案 `IF-0.2`，更新日期 2026-11-22。本文给出两组可据此开展工作的接口和验证分工；尚无本仓库版本的实机接口通过记录。具体端口见[板卡接口登记](../drone/design/board-interfaces.md)和[板间连接表](../drone/design/wiring.csv)。实际尺寸、电气读数和配置版本在对应设计与实验记录中登记，再通过 PR 固定版本。

双方联系人由成员在[分工表](team.md)中自行登记。机械臂组和无人机组分别核对本组输出，总负责人协调跨组依赖和接口分歧；具体技术接口由双方共同检查。

## 平台与原型依据

| 项目 | 当前依据 | 本阶段工作 |
| --- | --- | --- |
| 飞控 | 项目已确定 CUAV 雷迅 X25 Evo；[官方文档](https://doc.cuav.net/controller/x25-evo/)列出 ArduPilot/PX4 支持 | 登记实机固件、版本、参数文件和连接端口，验证实际采用的控制接口 |
| 机载计算 | 项目已确定 NVIDIA Jetson Orin 平台，载板型号尚未确定 | 登记具体子型号、实际载板、系统、JetPack 和依赖版本；先落实接口需求，再按所选载板分配物理针脚 |
| 现有机载原型 | 本地 `rod_perching_test` 使用 OAK-D Pro、固定横杆红色标记和 ArduCopter GUIDED | 先归档代码并锁定完整 Git 提交，再评估迁移到实机；相机和最终飞控固件不由这份原型自动定案 |
| 现有开关原型 | `switch_reader.ino` 通过 USB 串口发送触碰状态 | 由机械臂组归档示例，核对板型、电平、去抖和设备断连表现 |

## IF-01：机械安装、质量与重心

- 机械臂组交付安装面与孔位、紧固件、最大运动包络、夹口位置、组件实测质量与重心说明；制造件和打印件均关联设计版本。
- 无人机组交付机体安装区域、X25 Evo 与 Jetson Orin 的固定与散热空间、桨盘和线束净空、整机装配质量与重心记录。
- 两组用同一装配版本完成干涉检查和实物装配复核。图纸以 mm 标注尺寸、以 g 标注组件质量；控制代码使用的 m 与坐标轴另按 IF-05 转换。
- 完成条件：安装孔位、紧固方式、运动与桨扫空间均有图示和检查结果，组间引用的零件版本一致。实物尺寸在装配检查时测量记录，旧候选模型的数值不直接作为已通过数据。

## IF-02：供电、线束与接插件

- 无人机组负责整机配电以及 X25 Evo、Jetson Orin 的供电；机械臂组给出执行器、开关读取设备的输入要求和运行/峰值负载测量结果。
- 双方按实物型号与官方手册共同核对供电电压、电流能力、极性、连接器、引脚、信号电平、接地方式和线束固定。电源线、信号线在接线图中区分。
- X25 POWER C1/C2 输入为 10～18V；候选 PMU、电调、稳压和相机适配器的输入/输出分别见板卡接口登记。Jetson 载板未选型前不将旧图 J12/J16 分配写成最终接线。
- 候选图中的稳压模块或设定值先复核再沿用，尤其要核对实际 Orin 载板的输入要求；板载逻辑信号不能当执行器供电。
- 完成条件：接线图源文件与预览一致，端口逐项核对，记录上电、启动和执行机构动作时的电压及异常现象；无复位、接口误接或供电不足等未关闭问题后，再进入联合动作验证。

## IF-03：控制命令与执行结果

- 无人机组在 Jetson Orin 上处理视觉和任务状态，向 X25 Evo 发送飞行控制请求，并与机械臂组约定抓取请求和执行反馈。
- 当前把 X25 TELEM2 的 TX/RX/GND 登记为机载三线 UART 连接需求；所核对的厂商资料未明确该口信号电压，完成电平核实与载板选型后再确定直连或适配方式。
- 现有原型路线为 ArduCopter GUIDED 与 MAVLink，闭爪请求为 `MAV_CMD_DO_GRIPPER`。硬件支持 ArduPilot 不等于实机已安装正确固件；若改用 PX4，需要适配相应控制模式与命令处理。
- 机械臂组给出闭合/释放动作范围、执行约束和可观测反馈。已有原型只覆盖本轮触碰后的闭爪请求；释放、恢复和承重判定是后续交付。
- 状态应区分：触碰检测、命令已接收、实体闭合已观察、承重已验证、异常/未知。只收到 `COMMAND_ACK` 时记录命令处理结果，不能上报为已夹紧或可停桨。
- 完成条件：记录当前实际固件和参数，验证正常命令、拒绝/超时及停止请求；动作与日志可对应，组间字段含义一致。

## IF-04：触碰反馈与数据时效

以下数值来自现有原型代码，属于迁移时要复现和评估的基线，不是已测得的硬件性能：

| 项目 | 现有原型约定 | 联调检查 |
| --- | --- | --- |
| 传输 | USB 串口，115200 波特率，逐行文本 | 核对实物端口、换行解析及断连行为 |
| 触碰值 | `0` 松开、`1` 触碰 | 手动触发核对正反逻辑；非法行不得解释为有效状态 |
| MCU 采样发布 | 示例去抖 15 ms、每 20 ms 上报一次 | 测量实际间隔和触发延迟，记录是否需要调整 |
| 机载端失效判断 | 超过 0.25 s 无有效开关行则返回未知状态 | 在 `ALIGN` 或 `APPROACH` 停止数据后检查未知状态及任务退出，不能把未知当作松开；终止状态之后的持续监测另行设计 |

开关原型的触点接法只适用于其 `INPUT_PULLUP` 示例，具体 MCU 与 X25 Evo 的端口不能按示例引脚直接互换。机械臂组维护发送端，无人机组维护接收端和时效判断，双方共同记录触碰到停进请求及闭爪请求的日志。

## IF-05：定位、坐标与时间

- 无人机组负责 GPS 拒止场景下可用的定位/位姿来源及飞控接入。相机到目标的相对测量不能自动替代飞控所需的定位来源。
- 既有原型使用机体 FRD（前、右、下）表达相机到触发点偏移，控制距离用 m；代码内部角度用 rad，命令行安装角和偏航阈值使用度，必须注明所在接口的单位。
- 既有装配模型采用另一套图纸轴向，安装图、相机坐标、机体坐标和飞控坐标之间的变换需单独记录；由机械臂组提供实际触发点，由无人机组测量和验证外参。
- 完成条件：用已知方向的人工位移核对正负号和量级，保存相机到触发点的实测外参；定位数据有效且时效满足实际控制要求后，再进入飞控接近验证。[ArduPilot 外部位置估计文档](https://ardupilot.org/dev/docs/mavlink-nongps-position-estimation.html)作为采用该路线时的接入参考。

## IF-06：承重、动力管理与恢复

- 机械臂组负责夹持可靠性和独立承重证据，提供实际被夹物条件、载荷、保持时间、滑移/形变和异常记录。
- 无人机组负责飞行状态与载荷转移衔接、人工接管、动力管理及恢复流程的设计与验证。
- 现有原型到 `CONTACT` 后发闭爪请求，没有实体夹紧或承重传感判定，也没有载荷转移、停桨和恢复飞行流程。现阶段不能用 `CONTACT` 或 ACK 触发自动停桨。
- 完成条件：两组先依据实际整机质量、枝径/表面和夹口几何制定并记录试验条件及判定阈值，完成独立夹持与承重试验，再按已评审的联合方案验证动力与恢复流程。未经执行的项目状态保持“未执行”，结果不能由文档推定。
