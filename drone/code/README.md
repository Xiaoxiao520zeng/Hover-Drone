# 无人机代码与配置

保存飞控配置、机载视觉、目标对准和飞行任务衔接相关源代码及可复用配置。具体项目按需要建立子目录。

每个项目的 README 应写明：

- 功能、负责人及对应机体、飞控和机载设备版本。
- 开发与运行环境、工具及依赖版本。
- 配置、构建、启动或部署方式，必要参数及单位。
- 输入输出、坐标系、任务状态和异常处理方式。
- 验证步骤、预期结果和已完成的验证范围。

与机械臂组交互的指令和反馈格式统一引用[组间接口](../../docs/interfaces.md)。配置注明适用的硬件与软件版本；未确定的平台与参数标为“待确认”。编译产物、缓存、个人路径和密钥不入库。

## 现有原型及适用范围

工作区 `rod_perching_test/README.md` 描述一个**固定、近水平横杆与哑光红色标记**的对准及触碰联调程序，不代表自然树枝识别或自主停栖已经实现。原型使用 OAK-D Pro 的同步 RGB 与对齐深度；项目最终是否采用该相机仍待确认。

`requirements.txt` 中记录的原型环境为 Python 3.10 或更新版本，依赖范围为：

| 依赖 | 原型要求 |
| --- | --- |
| DepthAI | `>=3,<4` |
| NumPy | `>=1.23,<3` |
| OpenCV Python | `>=4.8,<5` |
| pymavlink | `>=2.4,<3` |
| pyserial | `>=3.5,<4` |

原型以 ArduCopter GUIDED 为飞控接口，要求可用的定位来源；无 GPS 场景需验证外部位姿输入与定点能力。[X25 EVO 官方说明](https://doc.cuav.net/controller/x25-evo/)列出 ArduPilot 与 PX4 支持，现有 ArduCopter GUIDED 因而是可评估的路线；仍需核对实机实际固件与版本、MAVLink 连接、定位和状态时效，完成接口联调。Jetson Orin 的具体子型号、载板、JetPack、系统与 Python 环境需登记。

## 代码交付与验证顺序

1. 整理现有原型并记录来源版本，提供依赖、启动、参数及模式说明；原始代码尚未导入本目录。
2. 明确模拟输出与实际设备输出的切换方式，记录固定横杆场景下的视觉结果、坐标符号、深度有效范围和相机到触发点的实测参数。
3. 核对飞控固件、定位、通信和指令方向，再与机械臂组验证触碰反馈、停进请求、闭爪命令及异常处理。
4. 通过[实验模板](../../experiments/TEMPLATE.md)登记条件、版本、日志位置、预期与实际结果，再据此推进联合实验。

原型将闭爪作为本轮试验终点；ACK 只表示命令处理，不证明实体闭合与承重。停桨、载荷转移、持续停栖和恢复飞行不属于已验证能力，需另行设计。当前未在本仓库登记程序运行或实机通过结果。
